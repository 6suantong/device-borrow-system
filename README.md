# 竞赛实验室设备借用管理系统 —— 四轮迭代分析与设计

围绕“设备借用管理系统”的软件工程系统开发方向考核项目：从原始需求出发，经历
**V1 需求分析 → V2 需求扩展 → V3 运行数据改进 → V4 部署运维** 四轮迭代，
每轮均在上一版方案基础上做增量演化（保留/修改/新增/删除）。

## 仓库结构

```
device-borrow-system/
├── report/     四轮迭代系统分析报告（docx）及其生成脚本
├── design/     代码设计：数据库 Schema（schema.sql）、领域模型与状态机
│               （domain_model.py）、API 契约（api-contract.md）
├── analysis/   V3 运行日志分析：分析脚本与证据链结果
├── deploy/     V4 部署与运维：容器编排、状态对账脚本、部署手册
└── docs/       版本变更日志（CHANGELOG.md）
```

## 四轮迭代速览

| 版本 | 主要输入 | 核心决策 |
|------|----------|----------|
| V1 | 原始需求材料 | 状态唯一可信 + 占用唯一性 + 全程留痕；设备分两级、流程分轻重 |
| V2 | 周会/访谈/管理员记录/群内约定 | 从流程管控到责任与透明：审批带理由、模糊约定正式化 |
| V3 | 529 事件 / 236 状态转换 / 549 请求 / 25 条反馈 | 证据驱动：占用事务化、异常归还事务化、超期治理、时限落地、幂等、性能 |
| V4 | 部署与运维约束 | 工程闭环：容器化、备份恢复、每日对账、任务告警、版本化迁移与回归 |

## 报告再生成

```bash
cd report
python fill_report.py --stage 4    # stage 1-4 分别对应 V1-V4 完成度
```

## V3 日志分析复现

```bash
cd analysis
python v3_log_analysis.py <V3材料包目录>   # 输出事件分布/状态转换/证据链统计
```

## Git 提交约定

四个主版本各一次提交（`git log --oneline` 可见演化过程）；
`design/`、`docs/CHANGELOG.md` 与报告同步演进。
