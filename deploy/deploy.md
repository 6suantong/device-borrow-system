# 部署与运维手册（V4）

## 1. 目标环境
- 实验室内网一台服务器/小型主机，Docker Compose 部署（见 docker-compose.yml）。
- 成员浏览器访问内网地址；无公网暴露面。
- 规模假设：约 40 人 / 33 台设备 / 两周 126 笔申请——单机单体足够。

## 2. 数据可靠性
- SQLite WAL 模式：断电/中断后事务一致，已有借用记录不丢失。
- 备份：每日 02:00 在线备份至 `backups/`（保留 30 天）；每周副本同步至
  实验室 NAS（异地）；**每月执行一次恢复演练**——备份不可恢复等于没备份。
- 发布前自动全量备份；迁移脚本只前向兼容（加列/加表，不改旧数据语义）。

## 3. 故障恢复
- 容器 `restart: always` + `/healthz` 健康检查，进程异常自动拉起。
- 服务恢复后（或每次发布后）运行对账脚本：

  ```bash
  python deploy/reconcile.py /data/lab_borrow.db
  ```

  退出码非 0 表示存在状态不一致，输出清单交管理员经受控修正入口处理。

## 4. 关键操作审计
- 审批/归还/状态修正/发布操作全部落 `event_log` + `approval_record`，
  日志表只增不删；每周自动导出归档至 NAS。

## 5. 版本发布与回退
1. 镜像按版本 tag 构建（`app:v3.x`）。
2. 发布前：跑核心回归（占用唯一性/状态机/定时任务/幂等）+ 全量备份。
3. 低峰窗口切换容器 tag，`/healthz` 恢复后执行对账脚本。
4. 回退条件：核心回归失败，或上线后 5xx>1%、对账不一致、P95>800ms。
5. 回退操作：切回上一版本镜像 tag；必要时恢复发布前备份。
